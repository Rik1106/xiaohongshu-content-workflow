# 偏好学习与维护 SOP
## 分类
| 输入 | 去向 |
|---|---|
| 数字错了、误引来源 | 内容事实更正及依赖结论，不是个人喜好 |
| 这篇标题更直接 | 当前任务；可记录 case_only |
| 以后测评都保留术语并解释 | 测评范围内的 active 偏好，保留原要求来源 |
| 多篇终稿都保留自嘲 | candidate，核对场景及反例 |
| 某平台审核异常 | 事件与原因假设，不立即成为禁词 |
| 技术操作反复失败 | 执行问题及方法候选，不写成人格偏好 |

## 每条记录
唯一 id；正向 statement；scope 至少说明账号/内容类型/任务范围；trigger；exceptions；evidence（案例/认可稿/日期及用户理由的必要摘要）；status；updated_at；supersedes（可选）。
status 为 case_only、candidate、active、superseded、retired。candidate 可以在当前任务中按请求使用，但不是长期强制规则。
数据最少化：保存可复现判断所需摘记，不默认复制原始私聊、真实身份或全部对话。原始材料留在用户自己的位置，公开包只保留空模板。

## 晋升条件
用户明确长期选择可以直接有效，无需机械等待三次。
推断偏好检查是否独立案例复现、是否有反例、是否特定体裁、是否只是旧模型的失误补丁。两个文档重复转录同一纠正不算两次证据。
个人风格进入个人配置或类别模式；只有可跨用户复用的操作方法才考虑进入公开 Skill。不能把个人明确选择推成平台最优实践。

## 冲突处理
当前用户要求优先。具体任务范围优先于模糊历史描述；若两条同范围 active 真冲突，使用当前明确要求，保留冲突记录，必要时只问影响当前产物的选择。
用户要求“今天例外”时不删除长期规则。用户要求“以后都不用”时退休对应条目并保留变更理由。
维护共享库时先读现状，合并指定条目，避免覆盖其他 Agent 的新增记录；有并发编辑条件时使用宿主可用的版本检查。

## 调用质量
把“别像 AI”还原成用户真正反对的现象，如空洞铺垫、作者身份错位、机械重复或不必要软化。记录正向目标及适用范围，不增长成禁词列表。
单次执行只加载最相关的有效偏好。熟练模型已能满足的泛泛提醒可停用，保留仍能改变判断的条目。

## 隐私与可撤回
记忆位置与范围明确，提供可查可改的文本记录。删除/退休按用户要求实施，不以“系统学习”作为拒绝修改的理由。
没有持久化能力时说清“本次可按此执行，未保存到长期记录”，不假装跨会话记得。
