# 复盘 SOP
## 判断顺序
1. 核对本篇目标及实际版本，记录制作/发布时间与观察窗。
2. 保留原始指标名、值、单位、范围；派生率写出分子分母。缺失不是零。
3. 比较同格式、相似受众/流量来源、相近成熟时间的内容；不匹配条件直接说明。
4. 看可观察差异，不直接确定因果。封面点击弱可检查承诺/画面/分发对象；没有分秒曲线无法定位前三秒。
5. 主页访问增加但关注少，可检查关注理由，也可能受既有粉丝、访问口径和来源影响。
6. 输出改变下一次动作的结论，保留替代解释。
下一轮假设必须锚定当前作品或账号已给材料。只收到指标、没有内容时，先给补证或测量动作；不要借相邻任务的主题替这篇设定题材、情节或受众。

## 小样本与迭代
题材和执行变量分开。不要依据一篇放弃全部方向，也不因一次高表现固化公式。
测试一个具体假设：改变什么、哪些条件尽量保持、看什么信号、什么结果会改变后续投入。
实际运营通常难以严格控制条件，多变量修改后用“迭代后观察”描述，不声称某一变量造成变化。
未改善时检查测量、分发、执行与目标是否匹配；不能无限加码，也不能仅凭第二条数据自动停止一个形式。

## 评论与人工终稿
区分独立用户、作者回复、重复提问、纠错、分歧和经验补充。有抽样就说明怎么选。
持续重复提问可能是说明缺口；高评论也可能是误解或争议。没有原文则保留语义未知。
人工终稿的删除、恢复、重排、事实校正分别记录。一次短句偏好先留在当前类别或案例，不能禁用所有长句。
官方点赞、回复、纠错、转发、资料支持与合作是不同事件；不能互相替代。

## 归档
小任务保存必要产物即可。单篇可保留：任务简报、认可/发布稿、关键修订、数据快照、代表性反馈、结论与下一动作。
周度整理由实际内容产生，后台 ID 与人类可读标题并存；不让使用者记编号。
保护个人资料和原始评论。归档路径由用户项目决定，示例默认 .xhs-work/。未经授权不写外部云文档或平台。

## 能力恢复
中断后读取当前状态、最近认可稿和最新观察记录。历史回填按原周期关联，用补录日期标明；周期由用户选择，不预置账号启动日期。
