# 来源与改写说明
本包从维护者长期的小红书内容协作方法重新编写，涵盖项目总控、素材研究、选题、图文迭代、短视频交接、单篇/周期复盘和偏好治理。没有复制原始聊天、后台截图、账号数据库或真实人物档案。

保留：长说明的动机链、前后台材料分工、素材到判断映射、认可稿保护、条件化规则、数据口径、偏好范围与规则减负。
改写：特定题材身份、写作气质、栏目配比、周次、工具和路径依赖。
移除：私人名称、联系方式、固定业务事件、求职流程、跨项目个人约束，以及将单条数据解释为确定原因的旧推断。

规范参考来自 COMPATIBILITY 中的官方文档。未包含第三方文风清理 Skill、图表库或插件源码；不要求安装它们。包内文字与 Python 辅助代码均为本次重新编写，MIT 授权范围为本仓库内容，不延伸到使用者导入的素材和第三方服务。

这里的经验方法不是平台推荐算法说明。状态/结构检查不证明用户增长；候选方法的验证范围见 VALIDATION。

## 从实际协作问题到公开规则
| 原工作中暴露的问题 | 保留的操作细节 | 本次调整 |
|---|---|---|
| 用户讲了很多动机，输出却只剩泛泛主题 | 先提取为什么做、希望读者得到什么、担心什么、认可哪些句子；材料映射到具体判断 | 不要求每次向用户复述长表，简单改稿直接执行 |
| 修改一个位置，已认可的其他部分也被改写 | 区分局部修改、全局方向变化、事实纠错；保护认可版本 | 回滚依赖实际保存的原稿，不能凭模型记忆声称精确恢复 |
| 旧事实已改，标题和其他卡片仍留着旧结论 | 列受影响组件并同步修正 | 将事实更新与风格学习分开，避免错误进入偏好库 |
| 卡片与正文重复，作品充满后台分析词 | 为不同载体安排不同任务；正文保留新增解释、体验或判断 | 不固化某位作者的口语、句长、情绪和互动结尾 |
| 视频复盘由单个指标直接跳到原因 | 记录时长、窗口、来源和替代解释，再安排下一次核查 | 不把平均观看当完播率；不把多变量迭代当因果实验 |
| 发布稿和助手稿混在一起，后续学习对象错误 | 用户确认发布事实与取得实际终稿分开记录 | 允许带缺口完成阶段复盘，不强迫重新做全账号策略 |
| 周复盘中已发布选题反复出现，补录覆盖历史 | 待做状态、发布关联、原事件日期和补录日期分别保留 | 移除私人周编号、固定发布配比和固定线程路由 |
| 一次纠正逐渐变成全局禁令 | 偏好记录范围、来源、例外和状态；规则可停用、退休 | 明确长期要求可直接生效；推断不按机械次数自动晋升 |

这些条目说明规则的来源和改写理由，不是各方法已被验证能提升流量的证明。新用户的领域知识、终稿和后续反馈仍需在自己的项目中校准。
